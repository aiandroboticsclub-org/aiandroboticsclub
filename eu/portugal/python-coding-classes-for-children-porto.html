Chapter 173 — LangChain Chains and Pipelines Explained: Connect AI Tasks Together

1. Introduction: What is a Chain in LangChain?

When building complex real-world AI applications, a single prompt to a Large Language Model (LLM) is rarely sufficient. Advanced workflows require performing multiple operations in sequence—such as summarizing text, translating it, and then answering questions based on that summary.

In LangChain, a Chain is a sequence of operations that connects multiple individual components into a single execution pipeline.

  ┌─────────────────────────────────────────────────────────────┐
  │                 Concept of a LangChain Pipeline             │
  ├─────────────────────────────────────────────────────────────┤
  │  Input Data ──► Component 1 ──► Component 2 ──► Final Output│
  │                 (Prompt)        (LLM Model)                 │
  │                                                             │
  │  • Components are linked using the Pipe Operator (|)        │
  │  • Output of Step N becomes Input to Step N+1               │
  └─────────────────────────────────────────────────────────────┘

Core Features of Chains:

  • Multi-Step Logic: Chains allow developers to build multi-step workflows where each step processes its input and passes its output directly to the next component in the sequence.
  • End-to-End Functionality: By linking prompts, models, output parsers, and custom utilities, chains enable end-to-end AI functionality within a single unified pipeline.
  • The Pipe Operator (|): In modern LangChain code, components are chained together using the pipe operator (|), making the flow of data clean and readable.

3. The 3 Fundamental Types of LangChain Chains

LangChain categorizes chains into three primary structural types based on how data flows through their components:

  ┌─────────────────────────────────────────────────────────────┐
  │                 3 Structural Types of Chains                │
  ├─────────────────────────────────────────────────────────────┤
  │  1. Sequential Chains ──► Step-by-step linear execution     │
  │  2. Parallel Chains   ──► Simultaneous execution            │
  │  3. Router Chains     ──► Dynamic path routing              │
  └─────────────────────────────────────────────────────────────┘

Type 1: Sequential Chains

Sequential Chains execute components linearly in a step-by-step order.

  • Data Flow: Component 1 processes the input and generates an output, which becomes the direct input for Component 2.
  • Example Workflow:
    1. Step 1: Summarize a lengthy article.
    2. Step 2: Translate the summary into French.
    3. Step 3: Generate a quiz based on the translated summary.

Type 2: Parallel Chains

Parallel Chains execute multiple components simultaneously rather than sequentially.

  • Data Flow: Inputs are passed to multiple independent chains at the same time.
  • Performance Benefit: Leverages multi-threading and parallel computing capabilities to process independent tasks concurrently, significantly reducing overall execution time.

Type 3: Router Chains

Router Chains dynamically select which execution path or component to trigger based on the user's input.

  • Data Flow: An incoming input is first analyzed to determine its nature, intent, or language. The router then directs the input down a specific branch of the workflow.
  • Example Use Case: A translation system that analyzes the input language first and routes the text to a specialized translation pipeline for that specific language.
  • Advancement: Increases system adaptability and efficiency in complex, multi-branch AI applications.

4. Practical Python Implementation — Building a Sequential Chain

Below is a complete hands-on Python example demonstrating how to construct and execute a sequential chain using LangChain Expression Language (LCEL) and the pipe operator (|).

A. Step-by-Step Python Script:

# =====================================================================
# Sequential Chain Example using LangChain and OpenAI (Topic 173)
# =====================================================================

import os
from dotenv import load_dotenv
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

# 1. Load API Keys from .env file
load_dotenv()

# 2. Instantiate OpenAI Model
# Using gpt-4o-mini for fast execution and low cost
# Setting temperature = 0.2 (20%) for precise, non-hallucinated output
llm = ChatOpenAI(
    model_name="gpt-4o-mini",
    temperature=0.2
)

# 3. Define Prompt Templates
# Prompt 1: Generates an outline from a topic
outline_prompt = ChatPromptTemplate.from_template(
    "Create a short outline for a lecture on this topic: {topic}"
)

# Prompt 2: Generates a full detailed lecture from an outline
lecture_prompt = ChatPromptTemplate.from_template(
    "Write a detailed lecture using this outline: {outline}"
)

# 4. Construct Chains using the Pipe Operator (|)
# Chain 1: Connects outline_prompt to the LLM
outline_chain = outline_prompt | llm

# Chain 2: Connects lecture_prompt to the LLM
lecture_chain = lecture_prompt | llm

# 5. Execute the Multi-Step Pipeline
target_topic = "LangChain Chains"

# Step A: Run Outline Chain to generate outline content
outline_result = outline_chain.invoke({"topic": target_topic})
outline_text = outline_result.content

# Step B: Pass generated outline as input to Lecture Chain
lecture_result = lecture_chain.invoke({"outline": outline_text})
lecture_text = lecture_result.content

# 6. Display Generated Outputs
print("=== GENERATED LECTURE OUTLINE ===")
print(outline_text)
print("\n" + "="*40 + "\n")
print("=== FULL DETAILED LECTURE ===")
print(lecture_text)

B. Code Explanation & Key Parameters:

  • load_dotenv(): Loads the secret OPENAI_API_KEY from the environment configuration file into the project execution context.
  • temperature=0.2: Controls model creativity. Setting a low temperature value (20%) forces the model to generate precise, structured answers while preventing hallucinations.
  • gpt-4o-mini: A fast, cost-effective language model suited for structured text generation tasks.
  • Pipe Operator (|): Links outline_prompt | llm into a unified chain where the template output flows directly into the language model.
  • Sequential Flow: The string content extracted from outline_chain is passed as the {outline} input parameter into lecture_chain, producing a detailed lecture complete with structured sections and closing remarks.
