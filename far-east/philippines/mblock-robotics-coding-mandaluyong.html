1. Introduction: Intentionally Generating Errors in Code

In earlier exception handling modules, the primary focus was on intercepting and handling errors generated automatically by Python at runtime. However, robust software design also requires the ability to intentionally generate errors ourselves.

  • Why generate errors intentionally? When code processes incoming data from users or external sources, Python's default runtime checks may not detect logical inconsistencies on their own.
  • Business logic & validation: If an application inspects data and encounters values that violate real-world rules or business logic—such as an impossible negative number for a person's age—it is dangerous to let the program proceed.
  • Instead of allowing faulty or illogical data to cause downstream bugs, the developer can explicitly trigger an exception using the raise keyword.

2. The raise Keyword and Error Anatomy

To manually trigger an exception, Python provides the raise keyword.

When using raise, you specify two key components:

  1. The exception type: Indicates the nature of the error (such as a ValueError, which signals an objection to the specific value of the data).
  2. The custom message: An explanatory text string detailing why the value is invalid or unacceptable.
raise ExceptionType("Descriptive error message")

Using this syntax alerts developers and surrounding code that an input check has failed and indicates where input validation or exception handling is needed.

3. Jupyter Notebook Example: Validating User Age

Step 1: Setting up the Input and Condition

Consider an application that accepts a person's age. If a user enters a negative value (such as -3), the code uses an if statement to verify that the value is non-negative:

# 1. Simulating an invalid user input
age = -3

# 2. Inspecting the value using an if statement
if age < 0:
    # 3. Explicitly raising a ValueError with a custom explanation
    raise ValueError("age cannot be negative")

4. Pairing raise with try...except for Controlled Handling

Raising an exception halts execution unless it is caught. In production applications, you can catch the custom-raised exception within a try...except block to log the error or prompt the user for valid data without terminating the program:

try:
    user_age = -3
    if user_age < 0:
        raise ValueError("age cannot be negative")
    print(f"User age recorded: {user_age}")

except ValueError as error:
    print(f"Validation Error caught: {error}")

Output:

Validation Error caught: age cannot be negative
  • The raise keyword triggers the ValueError when an invalid age is detected.
  • The except ValueError as error: block intercepts the error, extracts the custom text message, and prints a controlled notification instead of crashing the program.
